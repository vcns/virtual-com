virtual-com · Developer guide

Write the software behind the port.

Your application is the host end of each virtual port. This guide covers the .NET library, how the host end behaves, and the native interface for other languages.

In short

  • VirtualComDevices creates, lists and removes ports (admin)
  • VirtualComHost.Open("COM20") gives you a Stream
  • Reads return as soon as any data arrives
  • You control the CTS, DSR, DCD and RI lines the application sees
  • You can read the application's baud rate, line settings, DTR and RTS

Setup

Adding the library.

The library is src/Vcns.VirtualCom in the repository. It targets .NET 10 on Windows and has no package dependencies. Until it's published as a NuGet package, add the repository as a git submodule and reference the project:

git submodule add https://github.com/vcns/virtual-com.git external/virtual-com
<ItemGroup>
  <ProjectReference Include="external\virtual-com\src\Vcns.VirtualCom\Vcns.VirtualCom.csproj" />
</ItemGroup>

Example

Echo everything back.

The smallest useful host: everything the application on COM20 sends comes straight back. Run it, then open COM20 in any terminal program and type.

using Vcns.VirtualCom;

using var port = VirtualComHost.Open("COM20");
var buffer = new byte[4096];
while (true)
{
    int n = await port.Stream.ReadAsync(buffer);   // waits until the application writes something
    await port.Stream.WriteAsync(buffer.AsMemory(0, n));
}

Example

Bridge a port to TCP.

A minimal network bridge. The lines stay low until the TCP connection is up, so the application sees the "cable" only when there's something at the other end.

using System.Net.Sockets;
using Vcns.VirtualCom;

using var port = VirtualComHost.Open("COM20");
port.SetModemLines(ModemLines.None);                    // looks unplugged for now

using var tcp = new TcpClient { NoDelay = true };
await tcp.ConnectAsync("192.168.10.50", 5200);
using var network = tcp.GetStream();

port.SetModemLines(ModemLines.Cts | ModemLines.Dsr | ModemLines.CarrierDetect);

var state = port.GetState();
Console.WriteLine($"{state.PortName}: application open = {state.ComOpen}, {state.BaudRate} baud");

await Task.WhenAny(port.Stream.CopyToAsync(network), network.CopyToAsync(port.Stream));

A production bridge also needs time-outs, keep-alives, clean shutdown and error reporting. Bytes are never split, merged or reordered, but one read can return any number of them, so don't assume one read is one message.

Or use the ready-made bridge

The repository's VCNS Virtual COM Bridge does all of that already, with profiles, a tray menu, single-session protection and port creation. If it fits, use it as it is or as a branded edition (below) rather than writing your own.

Bridge

Building a bridge edition.

The bridge is three projects. An edition adds a fourth: a small executable with its own name and wording.

ProjectContents
src/Vcns.VirtualCom.BridgeThe engine: profiles and configuration, COM-to-TCP sessions, single-session locking, in-use detection, COM port inventory and allocation, the elevated port helper, and the embedded driver package. No user interface.
src/Vcns.VirtualCom.DesktopThe tray application, Settings window and dialogs. Its public entry point is BridgeApp.Run(BridgeEdition, string[]).
src/vcombridgeThe generic edition, VCNS Virtual COM Bridge.

A new edition is a Windows Forms executable that references Vcns.VirtualCom.Desktop and passes its BridgeEdition from an [STAThread] Main:

<ItemGroup>
  <ProjectReference Include="external\virtual-com\src\Vcns.VirtualCom.Desktop\Vcns.VirtualCom.Desktop.csproj" />
</ItemGroup>
[STAThread]
private static int Main(string[] args) => BridgeApp.Run(MyEdition.Instance, args);

The same executable also acts as its own elevated helper for creating ports, so Main must pass args through unchanged. The edition's properties are listed on the bridge page. NovaStar Proxy is built this way.

VirtualComPort is a record: InstanceId (for example ROOT\VCNSVCOM\0000), PortName, IsRunning, and ProblemCode (Device Manager's problem number when not running; 52 means the signature was rejected).

ModemLines is a flags enum: Cts (0x10), Dsr (0x20), Ring (0x40), CarrierDetect (0x80). These are the same bits GetCommModemStatus reports to the application.

VirtualComPortState.Parity uses the Windows constants: 0 none, 1 odd, 2 even, 3 mark, 4 space. StopBits is 0 for 1 stop bit, 1 for 1.5 and 2 for 2.

Semantics

How the host end behaves.

SituationBehaviour
Host reads, nothing bufferedThe read waits until the application writes. It never completes with zero bytes; cancel it (or close the host end) to stop waiting.
Host reads, data bufferedCompletes at once with up to the requested number of bytes.
Host writesCompletes once every byte is in the 64 KB buffer to the application. If the buffer is full, the write waits until the application reads.
Host writes, application doesn't have the port openCompletes at once; the data is discarded.
Application writes, no host attachedCompletes at once; the data is discarded.
Host end openedCTS, DSR and DCD are raised. The application gets CTS, DSR and RLSD events if it is waiting for them.
Host end closedAll lines drop. Data the application wrote but the host hadn't read is discarded.
Application closes the portIts pending reads, writes and waits complete as cancelled. Data the host wrote that it hadn't read is discarded.
Second open of either endFails with access denied, as with a real serial port.

Privileges

Admin operations in your application.

InstallDriver, Create and Remove change devices and need administrator rights. Everything else, including being the host end, works as a standard user. A good pattern is to run the privileged steps in a short-lived elevated copy of your own executable. Use ProcessStartInfo with Verb = "runas" and UseShellExecute = true, and pass the job in a file. That way the user approves one UAC prompt for a change, and your main process never runs elevated.

Failures throw Win32Exception (Windows Setup API errors) or InvalidOperationException (for example "COM20 already exists").

Other languages

Native interface.

Anything that can call Win32 can be a host. include/vcom.h in the repository defines everything below.

Interface GUID
GUID_DEVINTERFACE_VCOM_HOST = {13DBB15D-28F8-4AEB-81B8-C45B6F98B810}
Reference string
The interface path ends in \HOST; opening it makes you the host end.
IOCTL_VCOM_GET_PORT_STATE
0x001B6400; output VCOM_PORT_STATE (56 bytes).
IOCTL_VCOM_SET_MODEM_STATUS
0x001BA404; input a ULONG of VCOM_LINE_* bits.

Finding and opening the host end

Ask Configuration Manager for the interface on the port's device. Use CM_Get_Device_Interface_List with the device instance ID, or list all instances and match PortName through IOCTL_VCOM_GET_PORT_STATE. Then open it for overlapped I/O, so that a pending read doesn't block your writes:

#include <windows.h>
#include <cfgmgr32.h>
#include <initguid.h>
#include "vcom.h"

WCHAR paths[4096];
CM_Get_Device_Interface_ListW((LPGUID)&GUID_DEVINTERFACE_VCOM_HOST, NULL, paths,
                              ARRAYSIZE(paths), CM_GET_DEVICE_INTERFACE_LIST_PRESENT);
/* paths holds one NUL-terminated path per running port; pick yours, then: */
HANDLE host = CreateFileW(paths, GENERIC_READ | GENERIC_WRITE, 0, NULL,
                          OPEN_EXISTING, FILE_FLAG_OVERLAPPED, NULL);

ULONG lines = VCOM_LINE_CTS | VCOM_LINE_DSR | VCOM_LINE_DCD;
/* DeviceIoControl(host, IOCTL_VCOM_SET_MODEM_STATUS, &lines, sizeof(lines), NULL, 0, ...) */
