virtual-com · VCNS Tech Ltd

Virtual COM ports your software can sit behind.

virtual-com is an open-source virtual serial port driver for Windows 10 and 11. Each port has two ends. Any serial application opens the COM end as an ordinary COMn port, and your own software opens the hidden host end to feed it data. The host could be a network bridge, a device simulator, a logger or a test harness.

Status

Early development.

Not yet production-signed

The driver passes its full behaviour test suite on Windows 11 25H2 with Secure Boot on. Builds are currently signed with a test certificate, which Windows accepts only on PCs that have been told to trust it. Releases signed by VCNS Tech Ltd will follow. Until then, use it for evaluation and development. The user guide explains the test-certificate step.

How it works

One port, two ends.

Classic virtual serial tools such as null-modem emulators create a pair of COM ports and wire them back to back. virtual-com instead creates a single COM port whose far end is a private device interface. Only your software opens that interface, so it never shows up in port lists for users to pick by mistake.

COM end

A standard Windows serial port in the Ports (COM & LPT) class, listed in SERIALCOMM and by every port enumerator. Applications use the usual Win32 calls: CreateFile, SetCommState, SetCommTimeouts, WaitCommEvent and so on.

Host end

A private device interface on the same device. Reads complete as soon as any data is available, like a pipe. Two control codes tell the host what the application did (baud rate, DTR, RTS) and let it set the modem lines the application sees.

Modem lines

CTS, DSR and DCD are raised while the host end is open and dropped when it closes, so applications see the "cable" come and go. The host can change them at any time, for example to raise them only once its upstream link is ready.

Why user mode

No kernel driver, so no kernel signing problem.

Since Windows 10 version 1607, a new kernel-mode driver loads with Secure Boot on only if Microsoft has signed it. That means an EV certificate, a Partner Center account and a submission to Microsoft for every release. In April 2026, Windows 11 24H2 and later also stopped trusting the older cross-signed drivers that free virtual-serial tools relied on.

virtual-com is a user-mode driver. It is a DLL that Windows' own driver host loads into a normal process, under Microsoft's in-box reflector. None of its code runs in the kernel, so those rules don't apply. Windows needs only the driver package's catalog to carry a signature from a trusted publisher.

A fault in a user-mode driver makes Windows restart the driver host process, rather than stopping the machine.

Verified

Installed and tested on Windows 11 25H2 with Secure Boot on and test signing off. Windows reported the package as signed by a trusted Authenticode publisher.

Designed for

Windows 10 version 1809 and later, and all Windows 11 releases, on 64-bit x86 PCs.

Features

Behaves like a real serial port.

Win32 time-outs

All COMMTIMEOUTS modes, including "return immediately", "return on first byte" and total-plus-interval time-outs for reads and writes.

Events

WaitCommEvent for received data, event characters, buffer 80% full, transmit empty, and CTS, DSR, DCD and RING changes. .NET DataReceived and PinChanged work.

Status and purge

Bytes waiting in each direction (ClearCommError, BytesToRead), modem status, port properties, statistics and every PurgeComm flag.

Transparent data

No framing and no changes: all 8 bits pass through whatever the data-bits, parity or baud-rate settings say. Settings are stored and reported to the host.

Back-pressure

A 64 KB buffer in each direction. When it's full, writers wait (with write time-outs honoured) instead of data being dropped.

Your COM numbers

Ports are created with the number you ask for and claimed in Windows' COM name database, so nothing else is given it.

Full details are in the serial reference.

Bridge app

A ready-made host: the bridge.

The repository includes a complete host application, the VCNS Virtual COM Bridge. It's a tray app that gives serial software a COM port leading to a device's TCP port. You add a profile for each device, start it from the tray when you need it, and the bridge forwards bytes unchanged in both directions.

  • Connects only when you ask, and never reconnects by itself.
  • Protects devices that accept a single session, and reports Port in use rather than competing for it.
  • Numbers new ports clear of every COM port already on the PC.
  • Comes in branded editions, such as NovaStar Proxy for NovaStar LED controllers.

Read about the bridge

Server mode

The bridge also works in reverse. Real COM ports, such as USB-attached devices, each listen on their own TCP port, from a Windows service, so they can be reached and monitored over the network. Read about server mode.
