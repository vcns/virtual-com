virtual-com · Microsoft signing

From our signature to Microsoft's.

virtual-com doesn't need Microsoft's signature to work on 64-bit Windows 10 and 11. Getting one would let it install without a publisher prompt, run on ARM64 and reach PCs through Windows Update. This page is the plan for getting there, and where it stands.

Why

What Microsoft's signature adds.

Today the package's catalog is signed with an ordinary code-signing certificate. On 64-bit Windows 10 and 11 that is enough: a user-mode driver isn't subject to the kernel's signing rules. It leaves three gaps:

  • The install prompt. Windows asks the administrator installing the driver to confirm the publisher, unless that publisher is already trusted on the PC. Microsoft advises against pre-trusting a publisher for software distributed outside your own organisation.
  • ARM64 and S mode. Windows on ARM64 and Windows in S mode accept only catalogs signed by WHQL, Microsoft's certification signature.
  • Windows Update. Only drivers certified through the Windows Hardware Compatibility Program (WHCP) can be published to ordinary users through Windows Update.

S mode has a further obstacle: it runs only apps from the Microsoft Store, so the bridge app can't run there whatever the driver's signature.

The plan

Free steps first, then spend.

Everything that shows whether certification is possible costs nothing. Money is spent only once there's a passing test run ready to submit.

Before spending anything

1

Ask Microsoft the open questions

Ask on Microsoft Q&A, which is free and public, the two things Microsoft's documentation doesn't settle. Can a software-only, root-enumerated virtual COM port be certified, and under which device category? And can drivers for the hardware ID Root\VcnsVirtualCom be published through Windows Update, given that unusual hardware IDs get an extra review?

2

Run the Hardware Lab Kit ourselves

The Windows HLK, for Windows 11 24H2 and 25H2 and Windows Server 2025, is a free download. Its controller runs on English Windows Server, where the free evaluation edition will do, and it can be a virtual machine. The test system must be a dedicated physical PC with a clean install of the Windows version under test and Secure Boot off. It runs the test-signed package, so no Microsoft signature is needed to test.

Run the device fundamentals tests (Device.DevFund) against a VCNS port, fix whatever fails, and keep the resulting HLK package for submission. Later, repeat on Windows Server 2025 Datacenter to cover servers.

3

Make the package submission-ready

Repository work: a higher driver version for each release, symbols kept with every build, and an ARM64 build if ARM64 is wanted. See Package readiness.

Then pay, to submit

4

Buy an EV code-signing certificate

Only once step 2 passes. In VCNS Tech Ltd's name, from one of the certificate authorities Microsoft lists: Certum, DigiCert, GlobalSign, IdenTrust, Sectigo or SSL.com. It does two jobs. It's the identity Partner Center needs for registration, and it signs releases, so users no longer have to trust a test certificate.

The key has to be kept in hardware. A cloud-hosted key, rather than a USB token, lets CI sign releases through the workflow's Production environment (see Continuous integration).

5

Register for the Windows Hardware Developer Program

In Partner Center, sign in as a Microsoft Entra global administrator; a free tenant can be created during sign-up. Name a legal contact who can accept agreements and receive Microsoft's email, accept the code-signing and compatibility agreements, upload the EV certificate, then answer the business questionnaire Microsoft sends. A D-U-N-S number helps but isn't required.

6

Submit for certification

Submit the HLK package from step 2. Once Microsoft accepts the results, it signs the driver package. Attestation signing isn't needed on this path: it signs without testing, and its drivers can't reach Windows Update for ordinary users.

7

Publish through Windows Update

Create a shipping label for the certified package. Delivery is automatic, or manual, which shows the driver under Optional updates. Each release must carry a higher driver version than the one before, so PCs see it as an update.

Open questions

What isn't known yet.

  • Which certification category fits a software-only virtual COM port, and which HLK tests it runs.
  • Whether Windows Update offers driver updates to ports the app creates, whose hardware ID is root-enumerated.
  • Whether Hyper-V virtual machines are accepted as HLK test PCs.

Steps 1 and 2 answer them before any money is spent.
