virtual-com · User guide

Install the driver and create ports.

This guide is for administrators setting up virtual COM ports on a PC. If you're writing the software that sits behind a port, read the developer guide as well.

You'll need

  • Windows 10 1809+ or Windows 11, 64-bit
  • An administrator account, to install the driver and create or remove ports
  • The driver package (vcnsvcom.inf, .dll, .cat) and vcomctl.exe
  • About 5 minutes

Step 1

Get the files.

Signed releases will be published on the releases page. Until the first one is out, build the package yourself (see Build & sign), or use a test build supplied by VCNS.

Applications built on virtual-com usually carry the driver package and install it themselves. In that case, follow that application's guide instead of this one.

Step 2 · test builds only

Trust the test certificate.

Only for test builds

Production releases will be signed by VCNS Tech Ltd with a publicly trusted certificate, and this step won't be needed. Trusting a test certificate lets anything signed with it install on this PC, so do this only on machines you're evaluating on, and undo it afterwards.

Test builds come with vcom-test-signing.cer. In an administrator PowerShell window, run:

Import-Certificate -FilePath .\vcom-test-signing.cer -CertStoreLocation Cert:\LocalMachine\Root
Import-Certificate -FilePath .\vcom-test-signing.cer -CertStoreLocation Cert:\LocalMachine\TrustedPublisher

The first store makes Windows trust the certificate. The second stops Windows asking "Would you like to install this device software?" every time.

Step 3

Install the driver package.

In an administrator prompt, from the folder containing vcomctl.exe:

vcomctl install-driver C:\path\to\package\vcnsvcom.inf

This adds the package to Windows' driver store. You only need to do it once per PC, and again when you upgrade the driver: existing ports switch to the newer version.

Step 4

Create a port.

Pick a COM number nothing else uses. A safe habit is to go above every number already in use or reserved, including ports of USB adapters that are currently unplugged. Then:

vcomctl create COM20

Expected output:

Created COM20 (ROOT\VCNSVCOM\0000): running

The number is written to the device before the driver installs, so Windows keeps it. It is also claimed in Windows' COM name database, so no other device is given it later. Create as many ports as you need, one command each.

Step 5

Check it.

  • Device Manager → Ports (COM & LPT) lists VCNS Virtual COM Port (COM20). Double-click it: Device status should say "This device is working properly".
  • vcomctl list shows every virtual port and whether it's running: 
    COM20    running                      ROOT\VCNSVCOM\0000
  • The port also appears in HKLM\HARDWARE\DEVICEMAP\SERIALCOMM, which most applications use to list ports.

Using a port

What applications see.

Nothing on the host end
The application can open COM20. CTS, DSR and DCD are low, like a port with no cable plugged in. Anything it writes is discarded.
Host application attached
The lines rise (unless the host chooses otherwise), and bytes flow both ways unchanged.
Serial settings
Any baud rate, data bits, parity, stop bits or flow control the application sets is accepted, and reported to the host. None of it changes the data.
One at a time
Like a real port, COM20 can be open in only one application at a time; a second open gets "Access is denied". The host end is exclusive too.

A port does nothing useful until a host application opens its host end. The developer guide has a ten-line echo example to try.

Give it a name

Device Manager calls each port VCNS Virtual COM Port (COM20). To show what it's for instead, in an administrator prompt run:

vcomctl label COM20 "Workshop test rig"     # shown as "Workshop test rig (COM20)"
vcomctl label COM20                         # back to the standard name

The name also appears in programs that list ports by name. Updating the driver can restore the standard name.

Removing

Remove a port.

Close any application using it, then in an administrator prompt run:

vcomctl remove COM20

The device is removed and COM20 is released in the COM name database. You can also give the device instance ID shown by vcomctl list.

Uninstalling

Remove everything.

  1. Remove every port with vcomctl remove.
  2. Find the driver package: pnputil /enum-drivers, and look for Original Name: vcnsvcom.inf.
  3. Delete it, using its published name: pnputil /delete-driver oem42.inf /uninstall.
  4. If you trusted a test certificate, remove it: 
    Get-ChildItem Cert:\LocalMachine\Root, Cert:\LocalMachine\TrustedPublisher |
    Where-Object Subject -like 'CN=VCNS Virtual COM*' | Remove-Item

Developers working from the repository can run scripts\Uninstall-Test.ps1, which does all of this.

Troubleshooting

If something goes wrong.

vcomctl list says "not running (problem 52)"

Windows rejected the package's signature. With a test build, check the certificate was imported into both LocalMachine stores on this PC (step 2). With a release build, check the package files haven't been altered, because the catalog covers every file.

"Access is denied" from install-driver, create or remove

These commands change devices and need an elevated (Run as administrator) prompt. list works without it.

"COM20 already exists"

A virtual port with that name is already present. Run vcomctl list. To reuse the number, remove the existing port first.

An application can't open the port

Another application probably has it open, since each end allows one handle. Close it, or check with a tool such as Sysinternals Process Explorer (search for the port name). If the port isn't listed in Device Manager at all, it was removed or never created.

The application doesn't list the new port

Some applications only scan for ports when they start. Restart the application. If it still doesn't appear, check the port is running and listed in SERIALCOMM.

Where are the installation logs?

Windows records driver installation in %windir%\INF\setupapi.dev.log. Search it for vcnsvcom to see signature checks and any errors.
